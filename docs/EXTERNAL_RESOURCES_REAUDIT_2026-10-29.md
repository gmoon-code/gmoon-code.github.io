This stage continues from the fully passing Stage S1 internal-link graph, not from a new page-by-page restart. Scope is the **19 public HTML routes**, outgoing HTTP(S) links, embedded remote media and the two independently deployed GitHub Pages applications. Editor and development tools remain outside the public visitor audit. Earlier scholarly page source audits, the R1–R4 research page checks, U1 utility routes and CV1 are preserved.

## Repair and method

- Current `scripts/external_resource_audit.py` checks exactly the same 19 public routes as S1. It collects absolute HTTP(S) anchors, `img`/srcset media, remote embedded resources and application URLs. It does not claim to cover URLs dynamically assembled in JavaScript, CSS `url()` references or every future HTTP response.
- Uses eight bounded workers with seven-second request timeouts. A successful HEAD is recorded as reachable. If HEAD does not establish reachability, a GET request follows. A link is **confirmed missing only if HEAD and GET both indicate HTTP 404/410**; 403/429, timeouts, DNS and TLS failures remain *unverified*. No page source is edited automatically based on an error code.
- Added `scripts/verify-unverified-dois.py` for DOI identifiers whose publisher destination blocks automated requests. It checks DOI registration using Crossref, then DataCite, and independently checks OpenAlex when neither registry returns confirmation. OpenAlex is used only as secondary scholarly-index corroboration, never mislabelled as a DOI registration authority. DOI metadata index matches do not establish that the full text is freely available or that the citation title/year matches the published record.
- The existing `.github/workflows/external-resource-audit.yml` now runs both stages, writes a current compact `docs/EXTERNAL_RESOURCES_LATEST_RESULTS.json` and stores the full per-URL report, DOI metadata and diagnostic log as a temporary GitHub Actions artifact. The update is limited to the audit infrastructure, not the visitor-facing portfolio.

## Precise evidentiary limits

This is a bounded network availability and DOI metadata check. A HEAD success is not an end-to-end browser click, correct content identity or a guarantee against later link rot. Some HTTP errors are access-control responses rather than link failures. DOI registration and OpenAlex indexing are separate from checking every citation's author/title/year/source against its manuscript. Third-party page contents, interactive app behaviour, publisher authentication, user network access and dynamically generated external links are outside this stage.

**Stage S2 complete for this defined scope.** Next defensible cross-site stage is **S3, reference metadata and current public research-status alignment**, especially the still-separate OSF version/availability metadata, cited article-title/year consistency and portfolio versus CV degree/licence status. Any facts requiring private source records or formal conferral documents must remain explicitly unverified until those records are available.
