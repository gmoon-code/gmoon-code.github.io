## Actual code path and discovered defect

Current companion repository was fetched directly using the authenticated GitHub connector. Key source fingerprints at inspection:

- `README.md`, original SHA **dc0b2c2d4beba57fb9ab26d95bcea31017df8c5c**. Privacy section says Research Chat is optional; the browser minimizes selected project information, and **when project context is disabled it is removed before network serialization**.
- `assets/ai-helper-ui.js`, SHA **328bc9e440b6df9c76ba5209b4fe3a8adb853389**. Visible checkbox says **“Use my current project context”**. Privacy description says project responses are included **only while** that checkbox is on, although question and recent chat messages are still sent. The Chat form calls `RMSAIHelper.buildPayload(...)` and `RMSAI.chat(payload)`.
- `assets/ai-helper.js`, original SHA **1dae91ec28e52cefec79ab985901be099c57bccf**. When `includeProjectContext === false`, `buildPayload` still created an object containing `stage`, `research_path`, and `current_field`. **It did not put an explicit context-disabled flag on the payload.**
- `assets/ai-adapter.js`, SHA **942b44b8afe2cdf382d1f6bf525e0baed804bfc7**. `normalizeChatCall` returns a **neutral empty project context** only if `useProjectContext`, `includeProjectContext` or defined aliases are **explicitly false**. With no flag, it instead retains the provided `current_field` after its sensitive-key and recognizable-email/phone redactions. The adapter serializes the normalized context with the question and recent conversation history to the fixed Research Chat endpoint. Recognizable PII filtering is **not** equivalent to guaranteeing that all confidential free text is absent.

**Actual defect:** Disabling the UI checkbox still allowed a selected current notebook field to pass the source's context-minimization filter and become eligible for outbound serialization. A previous test only verified that the helper omitted the larger accumulated research chain, while a separate adapter test checked **explicit** false flags. Neither exercised the actual checkbox-to-adapter chain. The public project's technical note about no privacy/security certification remains important.

## Minimal actual correction

Three commits were made in the **companion application** repository `gmoon-code/research-methods`, not in the academic website's published HTML.

1. [Implementation commit 73559e4](https://github.com/gmoon-code/research-methods/commit/73559e4159559a0b837672c7dce16041acad3fbf). `assets/ai-helper.js` now returns `useProjectContext: include` and `project_context: include ? contextPacket(...) : {}`. When disabled, no stage, pathway or focused-field notebook information is assembled into the optional context object. The existing adapter's `contextExplicitlyOff` then supplies the canonical neutral context before serialization.
2. [Helper test commit 1caf8d3](https://github.com/gmoon-code/research-methods/commit/1caf8d3ad53dd7ff32283c1d6a4cd0b9a96b71fb). `tests/ai-helper-v212.test.js` now asserts both on and off flags and an **empty** context object when off. This legacy standalone script's modified file has been re-fetched, but its individual execution was **not** claimed from the automated workflow alone.
3. [Adapter regression commit 2d38d6a](https://github.com/gmoon-code/research-methods/commit/2d38d6a04a6dd5147302bea474c95307d0ae077c). `tests/adapter-contract.test.mjs` gained an integration test that loads the real `assets/ai-helper.js` into the adapter test's isolated runtime, simulates the checkbox-off state with a known **private notebook field sentinel**, sends the helper payload through the real `RMSAI.chat` network-normalization path using mocked `fetch`, and verifies that its **serialized request** contains a neutral context and no sentinel. The test also verifies that enabling context permits a selected field, while question text remains transmitted in both modes.

No backend service was redeployed or modified in this stage. The already existing adapter code handles the explicit opt-out signal. This is a **client-side correction**. Separate stage-help AI review routes require their own audit if the user's context checkbox is intended to apply globally across all networked prompts.
