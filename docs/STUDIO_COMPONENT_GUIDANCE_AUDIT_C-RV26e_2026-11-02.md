## Corrected factual overstatement

The original dynamically displayed column instruction said, “Column layout. Edit text inside each card, add a column or adjust the spacing.” This appeared in **all** selected column contexts, including existing `.grid-2` and `.grid-3` layouts. Actual module code enables adding/removing columns only if the selected context matches `.studio-columns`, `.studio-comparison` or `[data-studio-component=columns]`. On other grid layouts, the add/remove commands are disabled.

Revised the shared message to **“Edit text and spacing in this column layout. Adding or removing columns is available only in supported layouts.”** It retains access to available content and spacing tools while accurately qualifying structural editing. Only the generated instruction string was modified; the supported control set, disabled checks, table/column data or website pages were not changed. Commit [99a4405](https://github.com/gmoon-code/gmoon-code.github.io/commit/99a44057ca56534241214baf01d3fcae08590092).

## Other source-confirmed instructions

- **Tables:** `geometry()` requires matching column counts and every cell to have `colSpan===1` and `rowSpan===1` before structural commands become enabled. The dynamic status warns that merged/irregular tables remain text-editable but protect their structure. The general Studio guide already states the same limitation. Adding/removing rows or columns and undoing deletion are appropriate descriptions where controls are enabled.
- **Free movement:** The module describes offsets and per-screen reset, and uses arrow-key movement with Shift for larger steps and Alt for smaller steps. The source implements those numerical changes; actual pointer interaction was not tested. It attempts to release clipping on ancestor containers where necessary but does not guarantee that every element can be placed everywhere without downstream layout consequences.
- **Resizing:** The module's Shift flag can preserve an aspect ratio, and a separate “keep proportions” checkbox may lock it without Shift. The page distinguishes line endpoints from dimensions of other objects, and the reset text specifies the selected screen. Constraints on width/height mean no unlimited resizing capability is inferred.
- **Movements and diagrams:** The source generates placement-area and insertion guides; the Undo text is coherent with the change-history system, but its runtime correctness was not authenticated. The component tool protects the final process step and final FAQ question from deletion, and offers separate editing of each step/question/answer.

## Style and cohesion

The revised sentence names the current object, clarifies which operations may be unavailable and maintains direct, modest instruction. It does not rely on a stock contrast or promise user-visible behaviour beyond the implementation. The other dynamic help messages are short, concrete, and appropriately tied to the user's selected element or current screen. No evidence of a factual discrepancy justified more wide-ranging rewriting.
