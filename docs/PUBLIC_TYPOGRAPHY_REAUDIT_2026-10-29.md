## Scope and continuity

Continues the academic site's completed S1–S5 cross-page checks and all detailed route-specific audits without restarting them. Examines **18 directly readable public HTML routes**, excluding the deliberate legacy `about.html` redirect already audited under U1. Editors and separately hosted applications are outside the public visitor-facing scope. This stage addresses the open **WCAG 1.4.12-style text-spacing and WCAG 1.4.4-style 200% text enlargement** checks without claiming full accessibility conformance or physical native browser zoom.

Added `scripts/audit-public-typography.py` and `.github/workflows/audit-public-typography.yml`; they test checked-out production HTML/CSS/JS with Playwright 1.57.0 on Linux in Chromium and Firefox. Results, per-case geometry, screenshot captures and diagnostic logs are preserved in GitHub Actions. Text magnification is a *user-style simulation* doubling computed text sizes, **not** actual browser menu text-only zoom. The four text-spacing values are tested through overrides that model a user's priority over author styles, not through a native browser user-stylesheet installation.

## Test matrix and explicit standard

- **92 independent requirement cases**. For **all 18 pages**, Chromium tests 320px and 1280px CSS viewport widths separately with (a) increased text spacing and (b) 200% text size, for 72 cases. Firefox independently samples five public pages (Home, Research, AP Biology, Interests and CV) with the same two modes and widths, for 20 additional cases.
- In spacing mode the required values are **line-height at least 1.5 × font size**, **space after paragraphs at least 2 × font size**, **letter spacing at least 0.12 × font size**, and **word spacing at least 0.16 × font size**. Each is now independently asserted against computed sample paragraph styles. The test first injects a stylesheet and then uses direct important declarations to *approximate* the priority of user-origin accessibility preferences. This explicitly avoids the false result from a normal author stylesheet losing to more specific authored `!important` paragraph margins. Screen-reader-only `.new-tab-note` elements are excluded from visible clipping checks without deleting their accessible text.
- An additional **six exploratory combined-stress cases**, three pages per engine at 320px, apply **both** extreme spacing and doubled text simultaneously. They are deliberately tracked separately; a failure here cannot be silently labelled a pass, nor automatically used to claim noncompliance with either independently tested criterion.
- Each case checks page status, main landmark and H1, total document scroll width, reader text beyond the viewport, clipped reader text, and that text override styles actually took effect; narrow cases also exercise keyboard access to the Skip to content link. Full per-case geometry remains in the action artifact, while the compact latest result explicitly reports strict and supplemental failures separately.

## Verified production improvements

A sequence of bounded runs isolated real narrow-screen problems from test-only false positives.

1. Original run **40867407273** exposed **52** failures: some were hidden assistive notes incorrectly classified as clipped visible text, while others were real layout overflows with enlarged text.
2. After recognizing the deliberately visually clipped `.new-tab-note` text as screen-reader-only and instrumenting actual layout culprits, run **40867700898** showed **32** failures. The shared four-column mobile navigation was the most widespread problem: at 320px and doubled text, the Teaching navigation label extended to **353px**, forcing horizontal document scrolling on every direct page.
3. The first scoped mobile-navigation adjustment enabled link text wrapping; subsequent run **40867967565** reduced the count to **22**. Screenshot inspection found that allowing letter-by-letter breaking in the four-column grid was functionally resilient but visually poor.
4. A narrow-only scoped CSS update in `appearance.css` allowed long research text to wrap, confined research and teaching tables/figures to accessible **internal horizontal scroll regions**, permitted long equations and biology mechanism notes to wrap without concealing them, and prevented CV contact text from enforcing a minimum intrinsic page width. Subsequent run **40868257523** improved to **one** extra combined-stress failure, with all independent mode cases passing.
5. Replaced the fixed four-column navigation grid with a **flex-wrapped list of complete links** on screens up to 700px. This preserves link order and avoids unnecessarily splitting Research, Projects and Teaching into fragments when fonts are enlarged. Browser screenshot review confirmed that the larger navigation labels now remain intact and readable; its ordinary small-screen labels still wrap naturally. The prior scoped navigation and table rules remain source-controlled, with no changes to academic prose, assessment counts, figures or scientific claims.
6. A speculative extra 12px narrowing of the Action Research table scroll wrapper **did not improve** the residual combined-stress overflow; it was **reverted** instead of preserving an ineffective visitor-facing rule.
7. A first expanded assertion run **40869062525** revealed ten apparent paragraph-margin failures. The problem was the *test method*: an injected **author-level** stylesheet cannot override the more specific author-important paragraph margins as a browser **user-origin** important stylesheet can. The script now models the user's winning override explicitly and verifies each of the four computed spacing properties. No document's ordinary author margins were deleted or changed merely to appease that audit method.

The corrected production CSS passed fresh **S4 Chromium automated axe and reflow** and **S5 Chromium, Firefox and WebKit keyboard and forced-colour** workflows at the changed navigation source `4a620595` (runs **40869559839** and **40869559833**, both successful). A S6 screenshot contact sheet was inspected; it confirms readable 320px navigation without word-fragment columns after the flex adjustment, even under 200% simulated text enlargement.
