# C-RV29aa | Stage-review Research Chat, context consent and accurate feedback description

**Date:** 3 November 2026. **Resumed from:** C-RV29z. **Scope:** Companion Research Methods Studio stage-review network path, its existing Research Chat checkbox, actual adapter sanitization and the public academic website's optional-chat privacy wording. **Decision:** A separate substantive context-consent and feature-description problem was corrected in the linked application. An integration regression passed in CI. No academic website HTML wording change was needed. Whole-site academic content audit remains **In progress**.

## Source-bound scope

The academic visitor page `research-methods-studio.html` (unchanged blob `911924f5f3b22a3106984cf1b96e716fe1732b9d`) says student notebooks remain locally stored unless the user chooses a networked feature, that Research Chat is optional and that enabling context sends a minimized selection of project information. Its privacy paragraph cautions against entering identifiable participant records and its implementation paragraph explicitly avoids presenting technical design as an independent privacy or security assessment. These claims are precise only if all student-initiated Chat routes honour the disclosed context controls.

The companion `gmoon-code/research-methods` application contains two distinct Research Chat paths. C-RV29z corrected the main panel's **“Use my current project context”** checkbox, which previously left one notebook field eligible for outbound serialization when off. This stage separately inspects the stage's **“Ask Chat for deeper feedback”** button before and after correction.

## Identified second path mismatch

The original `assets/app.js` blob **cdc1412e311225b2210f814270f424329ebac4b1** created a stage-review payload containing `stage_id`, `project_context:stageContext()`, `student_work:stageStudentWork()`, local deterministic review flags, source context and course configuration. It passed that payload to `RMSAI.review` after the student clicked the review button, but **did not include any explicit context-enabled/disabled flag**.

The existing `assets/ai-adapter.js` `RMSAI.review` path sets `contextSource = payload.project_context` and calls `normalizeChatCall`, which **minimizes only the project-context object**. The supplied `student_work`, source lists, course configuration and local diagnostic flags were **not** serialized to the Chat service by this wrapper, because they were not added to the normalized `{question,history,context,mode}` request. The current `stageContext()` includes a limited project overview such as the research question, design, pathway, predictor and outcome, with unsupported properties filtered by the adapter's `SAFE_PROJECT_KEYS`. Thus the old button's **“deeper feedback”** label suggested a comprehensive look at a stage's written responses that the backend did not receive. More importantly, the request passed selected project-summary fields even when the main Chat panel's global-looking project-context preference was off, because `AI.review` lacked an explicit opt-out flag.

The button itself was a **deliberate network action**, so this was **not** an unattended automatic upload of every answer. It was an **opt-out consistency and transparency defect** concerning the narrower project summary that actually travelled. Recognizable-email/phone filtering and source-key allowlists are helpful but cannot independently guarantee removal of all sensitive free-text content.

## Implemented correction in the companion repository

Two follow-up commits were written to `gmoon-code/research-methods` on the default branch.

1. [Implementation commit 7993b8d](https://github.com/gmoon-code/research-methods/commit/7993b8d7592ee7b0e84d5a9ae0f436ee6c5284dd), modifying `assets/app.js`. The stage-review handler reads `project.aiHelper?.includeProjectContext !== false`, passes `useProjectContext` explicitly to the adapter and passes either the limited `stageContext()` summary or an empty `{}`. It adds the current **public curriculum stage title** so that a context-off request still contains a meaningful general stage question. The old unused `student_work`, deterministic flags, full source list and course fields were removed from this request assembly because the adapter previously discarded them anyway. The button now reads **“Ask Chat about my research plan”** in both idle and post-request states. A short adjacent note makes the scope transparent: the service uses a limited project summary only when the Research Chat context option is on, does not read all stage answers, and receives the explicit Chat request.
2. [Regression commit ce161e0](https://github.com/gmoon-code/research-methods/commit/ce161e0341e0f9cefa3443e4670da29357200f35), extending `tests/adapter-contract.test.mjs`. The test checks the actual `app.js` event-handler source for the opt-out flag and corrected description, sends mocked `RMSAI.review` requests under both flag conditions and verifies that **off** produces only the canonical neutral context and no known project-text sentinel, while **on** makes the selected research-question and design summary available. It also tests the generated stage question remains meaningful without privately identifying information.

This preserves the **user-authored Research Chat question and recent Chat history** as separately declared networked inputs when Research Chat is used; the stage-review path instead generates its own general question, and its context choice governs the additional project summary. It does not covertly pass full raw datasets or all stage responses. The change does **not** modify the Cloudflare Workers backend or certify service-side retention/security.

## Style and intellectual quality

The label correction reduces an unsupported implication of detailed student-work evaluation without weakening student choice. The new disclosure directly describes the actor, the network action and the limitation of the available evidence. It avoids promotional effectiveness language and does not imply that an AI assistant can independently verify data, sources or complete research reasoning. The visitor-facing project page remains conceptually coherent, moving from synthetic analysis to student research workspaces, backups and the limits of networked Chat.
